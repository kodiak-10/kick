# KickAI 商业化穿戴设备策略

更新时间：2026-06-07

## 结论

如果 KickAI 的目标是商业化，半 DIY 或长期依赖第三方封闭设备都只能作为验证阶段方案，不能作为核心商业壁垒。

推荐路线：

```text
验证期：第三方设备 + 文件导入 + BLE 心率
商业期：自有品牌硬件 / ODM 硬件 + 自有数据协议
专业期：自有硬件 + 视频分析 + 设备生态兼容 + 球队管理后台
```

## 为什么不能长期依赖半 DIY

半 DIY 的价值：

- 快速验证心率、比赛报告、App 交互。
- 低成本做 Demo。
- 帮助确认用户是否愿意为数据付费。

半 DIY 的问题：

- 传感器品牌不属于自己。
- 数据协议和导出权限不受自己控制。
- 商业宣传不能把第三方设备能力包装成自己的核心能力。
- 厂商 API 改动或关闭后，产品链路会断。
- 批量发售涉及认证、售后、质保和电池安全，DIY 方案很难承担。

## 商业化要掌握的核心资产

KickAI 最应该掌握：

- 自有用户账号与运动数据资产。
- 自有比赛数据模型。
- 自有视频 + 穿戴数据融合算法。
- 自有硬件数据协议或至少可控的 ODM 固件协议。
- 自有训练建议和球队报告生成能力。

不一定一开始就掌握：

- 完全自研传感器芯片。
- 完全自建硬件工厂。
- 职业级 EPTS 精度认证。

## 推荐硬件路线

### 方案 A：ODM 白牌硬件，自有品牌

适合 KickAI 第一代商业硬件。

做法：

- 找成熟运动穿戴 ODM。
- 使用成熟 BLE 芯片、GPS、IMU、心率方案。
- 要求固件开放自定义数据协议。
- 外观和 App 做 KickAI 自有品牌。
- 数据直接进入 KickAI 云端和 App。

优点：

- 比完全自研快很多。
- 可以掌握品牌和数据。
- 能做小批量试产。
- 后续可逐步替换关键模块。

必须签进合同：

- 原始数据归属 KickAI 和用户。
- 固件协议文档归 KickAI 使用。
- 可导出原始数据。
- 不得绕过 KickAI 直接运营用户数据。
- 硬件 ID、设备密钥、云端绑定逻辑由 KickAI 控制。
- 支持后续 OTA。
- 生产测试工具和校准流程交付。

### 方案 B：完全自研硬件

适合第二代或专业版。

模块：

- BLE SoC：Nordic nRF52 / nRF54 系列或同类方案。
- GPS/GNSS：10Hz 以上更适合足球跑动。
- IMU：6 轴或 9 轴，用于加减速、冲击、姿态趋势。
- 心率：胸前 ECG 优先于腕式 PPG。
- 电池：小容量可充电锂电池，必须考虑安全认证。
- 外壳：背心背部 Pod，胸前电极或独立心率带。

优点：

- 数据、协议、算法、品牌完全可控。
- 可以形成长期壁垒。

缺点：

- 成本、周期、认证、售后压力大。
- 需要硬件、固件、射频、结构、供应链团队。

### 方案 C：只做软件，兼容多设备

适合早期快速增长。

做法：

- 支持 Polar / Garmin / FIT / GPX / CSV / POSSIBALL 等导入。
- App 侧展示统一比赛报告。
- 不卖硬件，只做数据平台。

优点：

- 最快上线。
- 没有硬件库存和售后压力。

缺点：

- 商业壁垒较弱。
- 数据质量不可控。
- 用户体验依赖外部设备。

## 建议的产品阶段

### 0-3 个月：验证期

目标：

- 证明用户愿意上传比赛视频和体能数据。
- 做出比赛报告体验。

技术：

- BLE 心率接入。
- CSV/FIT/GPX 文件导入。
- 视频时间线同步。
- 手动标记换人时间。
- 手动锁定目标球员。

采购：

- Polar H10 1-2 条。
- POSSIBALL / SoccerBee / STATSports 任意 1 套用于样例对比。

不要做：

- 不要批量采购。
- 不要承诺职业级精度。
- 不要把第三方设备数据包装成自研能力。

### 3-9 个月：商业试点

目标：

- 做 KickAI 自有数据格式。
- 做小范围球队/青训试点。
- 找 ODM 试产自有品牌设备。

技术：

- 自有设备绑定。
- 自有数据协议。
- 云端比赛报告。
- 训练负荷趋势。
- 球队多人管理。

商务：

- 与 ODM 签数据归属和固件开放条款。
- 找 2-3 支球队试用。
- 收集真实售后问题。

### 9-18 个月：自有硬件商业化

目标：

- KickAI 背心 / Pod 小批量发售。
- App + 硬件 + 报告订阅打包。

技术：

- 固件 OTA。
- 数据加密。
- 设备校准。
- 批量生产测试。
- 设备售后管理。

合规：

- Bluetooth Qualification。
- 中国无线电发射设备型号核准 / SRRC。
- 电池运输与安全测试。
- 隐私合规与用户授权。

## 数据权限与商业合同红线

采购或合作前必须确认：

- 数据能否导出。
- 是否允许商业 App 使用。
- 是否允许二次分析并展示给用户。
- 是否允许训练模型。
- 是否有 API 调用次数限制。
- 是否禁止竞品或第三方平台接入。
- 用户数据属于谁。
- 如果停止合作，历史数据能否迁移。

合同里建议写：

- 用户原始运动数据归用户所有。
- KickAI 获得在用户授权范围内的处理、展示、分析和存储权。
- 设备厂商不得单方面关闭数据出口。
- API 停止服务必须提前通知。
- 必须提供数据字段说明和版本变更记录。
- 数据不得用于厂商自己的广告或二次售卖，除非用户另行授权。

## 数据隐私与合规

心率、位置轨迹、身体负荷、比赛视频都属于高敏感运动数据。

商业化需要：

- 明确隐私政策。
- 单独获取健康/位置/视频处理授权。
- 支持用户删除数据。
- 支持导出个人数据。
- 未成年人需要监护人授权。
- 不做医疗诊断宣传。
- 不写“心脏异常诊断”等医疗结论。

产品文案建议：

```text
本产品用于运动表现分析和训练参考，不用于疾病诊断、治疗或医疗监测。
```

## 硬件认证提醒

如果自有品牌销售含蓝牙的硬件：

- 需要完成 Bluetooth SIG Qualification。
- 在中国销售含无线发射模块的设备，需要关注 SRRC 型号核准。
- 含电池产品需要做电池安全、运输测试和相关认证。
- 如果声称医疗监测或疾病诊断，可能触发医疗器械监管，应避免。

## KickAI 推荐路线

最适合当前阶段：

```text
第一步：第三方设备验证数据体验
第二步：文件导入 + BLE 心率 + 视频同步
第三步：寻找 ODM 做 KickAI 自有背心/Pod
第四步：自有协议和云端报告
第五步：球队版订阅 + 自有硬件销售
```

第一代自有硬件不建议太复杂。

建议第一代硬件只做：

- 心率
- GPS 轨迹
- 速度
- 距离
- 冲刺
- IMU 加减速
- 设备时间戳

不要第一代就做：

- 精准触球识别
- 战术事件自动识别
- 医疗级心电报告
- 多球员无感自动身份识别

这些应交给视频分析和后续算法迭代。
